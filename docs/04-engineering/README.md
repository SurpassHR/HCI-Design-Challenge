**语言：[中文](README.md) | [English](README.en.md)**

## 当前状态

已完成**系统设计 → 模块设计**的技术设计基线，并发布 NutriPal React/Vite/TypeScript 原型。当前包含 8 个核心页面、F07a–l 菜谱详情与替换流、Mock Repository、显示偏好、91 道菜谱 Mock 搜索和 25 条测试；真实后端、数据库和第三方服务仍待决定。

## 设计顺序

1. [系统设计](system-design.md)：边界、架构、领域模型、API 契约、安全与非功能约束。
2. [模块设计](module-design.md)：路由、模块职责、状态、仓储接口、错误处理与验收场景。
3. [ATDD 原型脚手架](atdd.md)：验收条件、RED→GREEN 记录、已实现范围与人工停止点。

系统设计先于模块设计；模块文档不得新增系统设计中未定义的数据所有者或外部依赖。

## 已明确的边界

- 首版是移动端优先的 Web/PWA 参考设计，390px 为设计基准；具体平台仍待确认。
- 当前脚手架已包含 Web App Manifest、应用图标与生产环境离线 shell。
- 前端技术方向已确认：TypeScript + 前端组件，后端接口预留。
- 前端只通过 Repository/API Client 获取领域数据；UI 不直接访问第三方 API 或浏览器存储。
- 后端预留为模块化单体，API 前缀固定为 `/api/v1`；本阶段不实现服务端。
- Mock 与未来真实 API 共用同一请求、响应、错误和超时契约。
- F04、F05、F06 的真实通知、GPS 和图像识别使用 Provider 接口预留，首版为模拟能力。
- 健康、位置、饮食与偏好数据需要最小化处理；原始图片和精确轨迹不得持久化。
- 首版无登录、云同步、支付或真实配送。
